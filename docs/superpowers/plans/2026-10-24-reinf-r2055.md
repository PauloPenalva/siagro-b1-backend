# EFD-Reinf R-2055 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transmitir à Receita (EFD-Reinf 2.1.2) a retenção do Funrural das compras de produtor rural — R-1000, R-2055, R-2099, R-2098, R-9000 — com consulta assíncrona do lote e guarda de recibos, só em STANDALONE.

**Architecture:** `SiagroB1.Fiscal/Reinf/` monta XML, valida no XSD, assina (SignedXml) e fala com a API (interface `IReinfClient`). `SiagroB1.Application/Services/Reinf/` apura a partir das linhas do Documento de Entrada (mesma seleção do `FunruralWithholdingReportService`), persiste eventos/lotes/períodos e orquestra. Web expõe ações OData; Hangfire consulta lotes pendentes. Frontend: telas `reinf` e `reinfSettings` no menu Fiscal.

**Tech Stack:** .NET 10, EF Core SQL Server (InMemory nos testes), xUnit, Hangfire, System.Security.Cryptography.Xml, OpenUI5 TS + OData v4.

**Spec:** `docs/superpowers/specs/2026-10-24-reinf-r2055-design.md`

## Global Constraints

- Worktrees: backend `C:\Projetos\SiagroB1\siagro-b1-backend-reinf`, frontend `C:\Projetos\SiagroB1\siagro-b1-frontend-reinf`, branch `feature/reinf`. Nunca push; commit por tarefa; `git add` todo arquivo novo; mensagem `tipo(escopo): ...` pt-BR com trailer `DB:` quando houver migration (escopo `reports` para o fiscal/REINF, `platform` para menu).
- Identificadores em inglês; textos de tela e mensagens de erro em pt-BR.
- Layout 2.1.2; XSDs em `SiagroB1.Fiscal/Schemas/Reinf/v2_01_02/` (copiar para saída como EmbeddedResource ou Content, como os Schemas do MDF-e).
- Valores decimais com vírgula, 2 casas (`\d{1,12},\d{2}`); `nrInsc` do contribuinte = raiz 8 dígitos; `nrInscAdq` = CNPJ 14 da filial.
- Id: `"ID" + "1" + raiz.PadRight(14,'0') + yyyyMMddHHmmss (Brasília) + seq:D5` (36 chars).
- Endpoints: `https://pre-reinf.receita.economia.gov.br` (ProductionRestricted, tpAmb 2, padrão) e `https://reinf.receita.economia.gov.br` (Production, tpAmb 1); `POST /recepcao/lotes`, `GET /consulta/lotes/{protocolo}`.
- Máximo 50 eventos por lote; um grupo por lote.
- Só STANDALONE: menu `StandaloneOnly = true` e serviço recusa com a mensagem `FiscalConferenceController.StandaloneOnlyMessage` (reusar a constante).
- `verProc` = versão do assembly Web; `procEmi` = 1.
- Valores lidos da fotografia da linha (`FunruralBase`, `Funrural*Value`), nunca recalculados — exceto `vlr*NRet` do processo judicial.

## Review Focus

1. Devolução lançada depois de o período já ter sido aceito → evento fica `Outdated`, retransmissão gera `indRetif=2` com o `nrRecibo` anterior (teste na Task 6).
2. Produtor que tinha evento aceito e ficou com bruto 0 (devolução total) → R-9000, não R-2055 zerado (teste na Task 6).
3. Lote ainda em processamento (`cdResposta` 1) na consulta → nada muda, continua `Processing`; resposta com HTTP 5xx ou timeout → lote não some, erro gravado e retentável (testes na Task 8).
4. Mais de 50 eventos no período → vários lotes (teste na Task 7).
5. Transmitir/fechar com período `Closed` → bloqueio "Período fechado: reabra (R-2098) antes de enviar." (teste na Task 9).
