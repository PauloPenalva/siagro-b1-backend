# ECF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** gerar, por CNPJ raiz e ano, o TXT da ECF do Lucro Real (IRPJ/CSLL) importável no PVA.

**Architecture:** sobre o branch da ECD. Parâmetros da ECF + quadro societário + ajustes do LALUR/LACS
(entidades novas, OData no Web); loader em `SiagroB1.Reports/Services/Ecf` que reaproveita o
`EcdDataLoader` (contas, saldos, visões) e soma os ajustes; calculadora pura do IRPJ/CSLL; file service
com `SpedRecordWriter`; validator; controller `/reports/Ecf`; três telas UI5.

**Tech Stack:** .NET 10, EF Core, xUnit, OpenUI5 + TypeScript.

**Spec:** `docs/superpowers/specs/2026-10-23-ecf-design.md`

Worktrees: backend `C:\Projetos\SiagroB1\siagro-b1-backend-ecf`, frontend `C:\Projetos\SiagroB1\siagro-b1-frontend-ecf`, branch `feature/ecf` (criado de `feature/ecd`).

## Global Constraints
- Só STANDALONE. ISO-8859-1, `|REG|...|` CRLF (via `SpedRecordWriter`).
- Um arquivo por CNPJ raiz e ano civil; declarante `/0001`.
- Blocos J/K com os mesmos números da ECD do ano (mesmo loader/calculadores).
- IRPJ = 15% × lucro real + 10% × (lucro real − 20.000,00 × meses do período), adicional nunca negativo; CSLL = 9% × base. Arredondamento 2 casas, meio para cima.
- Compensação de prejuízo/base negativa limitada a 30% do lucro antes da compensação (bloqueia acima).
- Identificadores em inglês, telas/erros pt-BR; commits `feat(reports): ...`; `DB:` trailer com migration; never push.

## Review Focus
1. Prejuízo no período → IRPJ e CSLL zero, adicional zero (nunca negativo).
2. Trimestral: adicional sobre 60.000,00 por trimestre; anual: 240.000,00.
3. Ajuste "ambos" entra no M300 e no M350.
4. Quadro societário com % somando 99,99 por arredondamento → aceitar tolerância 0,01.
5. Anual: estimativa de cada mês pelo balancete acumulado até o mês (suspensão/redução), menos o já devido nos meses anteriores, nunca negativo.

### Task 1: Cadastros (Domain/Web/Migrations)
- `EcfSettings` (PK BranchCode): `AssessmentForm` (Annual/Quarterly), `MainCnae` (7 dígitos), `LegalEntityQualification` (2 dígitos, padrão "01"), `PreviousEcfHash?`, `UpdatedAt/By`.
- `EcfPartner` (Id, BranchCode, Name, TaxId, Qualification (2 dígitos, tabela da ECF), VotingCapitalPercent, TotalCapitalPercent, CountryCode padrão "105").
- `EcfAdjustment` (Id, BranchCode, Year, Period (1-4 trimestral / 0 anual), Tax (Irpj/Csll/Both), Kind (Addition/Exclusion/LossOffset), TableCode, Description, Amount, LedgerAccountCode?, PartBAccountCode?, PartBAccountName?).
- OData CRUD (sets `EcfPartners`, `EcfAdjustments`) e Get/Save dos parâmetros (padrão `EcdSettingsController`, com a mesma regra de rejeitar chave ausente). Validações pt-BR.
- Migrations `AddEcfTables` (App) e `AddEcfMenus` (Common: `ecf`, `ecfSettings`, `ecfAdjustments` sob `accounting`, depois do último item).
- Testes de serviço/controlador; commit com `DB: AddEcfTables, AddEcfMenus`.

### Task 2: Calculadora do IRPJ/CSLL (pura)
- `SiagroB1.Reports/Services/Ecf/IncomeTaxCalculator.cs`: `IncomeTaxResult Compute(decimal bookProfit, decimal additions, decimal exclusions, decimal lossOffset, int months)` → `{ AdjustedProfit, OffsetApplied, TaxableIncome, Irpj, IrpjSurtax, Csll… }` (uma chamada para IRPJ e outra para CSLL, com os ajustes de cada tributo).
- Testes cobrindo Review Focus 1, 2 e o limite de 30%.

### Task 3: Carga + arquivo + validação + endpoint
- `EcfDataLoader` (reaproveita `EcdDataLoader` e lê parâmetros, sócios, ajustes), `EcfFileService`, `EcfValidator`, `EcfController` (`/reports/Ecf/Check`, `/reports/Ecf`, `ECF_<CNPJ>_<AAAA>.txt`).
- Registros, campos e ordem pelo Manual da ECF do leiaute vigente (tabela de versão em um lugar só, comentada): os do spec. Lucro antes do IR do período = resultado das contas de resultado antes do encerramento (K355) no período.
- Anual: N620/N660 mês a mês pelo balancete acumulado (Review Focus 5); N630/N670 do ano. Trimestral: N630/N670 por trimestre.
- Bloqueantes do spec + todos os da ECD que se aplicam (reusar `EcdValidator`).
- Testes de geração (contagens do bloco 9, J/K iguais à ECD, M300/M350, N630/N670 com a calculadora) e de validação.

### Task 4: Telas

- `npm run ts-typecheck` e `npm run lint` limpos.
